# 실서식 추출 정답셋 (첫 배치)

03_데이터정의 §3.2 스키마의 정답 JSON + 가공 값이 채워진 PDF. 문서 목표는 30~50건이며 이것은 **첫 배치**다.

- 35개 서식(native) + 13개 스캔 변형(scan) = 48개 정답 문서, 262개 라벨(값이 있는 필드).
  - `kr_national_*` / `kr_local_*` (13): 국가법령정보센터 공식 PDF 레이아웃. 값 칸의 빈 서식 문구를 지우고(괘선 유지) PyMuPDF로 값을 씀.
  - `ftc_*` (21), `pps_stockpile_lease_2004` (1): HWP 5.x. LibreOffice에 HWP5 필터가 없어 파이프라인은 파싱 텍스트를 A4로 흘려 그린다(`render_lines_to_pdf`). 파싱 블록의 빈칸에 값을 넣고 같은 방식으로 렌더 = 채워진 HWP를 올렸을 때 파이프라인이 만드는 PDF와 같다.
  - `*_scan` (13, 법령 서식): 200dpi 래스터, ±1–3° 회전, 노이즈, JPEG. bbox는 같은 아핀 행렬로 변환(회전된 사각형의 외접 사각형).
- 값은 전부 가공(doc_id 시드 고정). 사업자등록번호는 `biz_no_checksum_ok` 통과하는 가짜 번호. 기관·회사명은 가상.
- 채권자(creditor) = 보증·대금을 받는 쪽: 법령 서식은 발주처/납부서의 `귀하` 수신인, 공정위 서식은 원사업자. 상대방(계약상대자·수급사업자)에도 다른 가공 값을 채워 혼동 사례로 둠(정답 아님).
- 서식에 해당 칸이 없으면 `null` (예: 법령 서식의 채권자 사업자번호, 공정위 서식의 보증기간). `kr_national_14`, `kr_local_13`(각서)는 전부 `null`인 오탐 점검용.
- bbox: [x0,y0,x1,y1] 0~1, 좌상단 원점, **값 텍스트만**의 사각형(라벨 제외). 기간 중 이행기일은 종료일 부분만.

재생성: 저장소 루트에서 `backend/.venv/bin/python data/gold/forms/make_gold.py` (결정적).

> **라벨은 프로그램으로 생성했다. 문서는 수작업 라벨을 요구하므로 사람이 PDF를 열어 표본 점검(spot-check)해야 한다.**
