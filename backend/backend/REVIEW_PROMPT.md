# 리뷰 요청 프롬프트 (다른 AI에게 전달용)

아래 내용을 그대로 다른 AI(예: 별도 세션의 Claude, ChatGPT 등)에게 붙여넣어 검토를 요청하세요.
`backend/` 폴더 전체(README, docs/*.md, app/**)와 `front 폴더/src/types/api.ts`,
`front 폴더/src/mocks/handlers.ts`를 함께 첨부하거나 열람 권한을 주면 됩니다
(백엔드가 실제 프론트 계약과 맞는지 대조하는 것이 이번 리뷰의 핵심이기 때문).

## 프롬프트

너는 "AI 기반 계약서 검증 및 규정 챗봇 시스템" 학기 프로젝트의 시니어 백엔드 리뷰어야.
`backend/` 폴더에는 설계 문서(`docs/`, 4주차 산출물 형식)와 함께, **API 34개 엔드포인트가
실제로 동작하는 구현**(DB 연동, JWT 인증, 파일 저장, 규칙 기반 AI 로직, SSE 스트리밍)이 있어.
AI 모듈(`app/services/ai_client.py`)은 외부 OCR/LLM API 키 없이 돌아가도록 정규식/BM25 등
결정적 로직으로 구현되어 있고, 이 인터페이스 뒤에서 나중에 실제 모델로 교체할 계획이야.
아래 기준으로 리뷰해줘.

### 배경 (판단 기준)
- 프로젝트 목적: 계약서 주요정보 자동추출 + 원문 위치(BBox) 연결 + 위험조항 탐지 + 규정 RAG 챗봇
- 팀 구성: AI·Document 담당 / **Backend·Data 담당(이번 리뷰 대상)** / Frontend·RAG 담당, 총 3명
- 성능 목표: 정보추출 정확도 90%+, BBox 매핑 성공률 95%+, 규정검색 Recall@5 90%+, 근거없는 챗봇 응답 5% 이하, 주요기능 정상동작률 95%+
- `backend/README.md`의 "구현 현황과 한계" 표에 현재 AI 로직의 의도된 단순화 지점이 정리되어 있음 — 이건 이미 알려진 제약이니 "AI가 부실하다"는 지적보다는, **그 제약 안에서 백엔드 코드 자체가 올바른지**에 집중
- 학기 프로젝트 범위 조정: EBIZ/KOINS 실연동 제외(Demo UI로 대체), 수기체 OCR 제외, 대규모 Graph DB/Ontology 대신 경량 벡터+키워드 검색

### 리뷰 관점
1. **프론트 계약 일치 여부(최우선)**: `app/api/*.py`의 실제 응답이 `front 폴더/src/types/api.ts` ·
   `src/mocks/handlers.ts`와 정확히 일치하는지 — FieldCode 8종, bbox 0~1 정규화, 에러 포맷
   `{error:{code,message,detail}}`, SSE 이벤트 순서(status→token→citation→done), 페이지네이션 포맷
2. **DB 트랜잭션/무결성 정확성**: `app/services/pipeline.py`의 백그라운드 파이프라인이 실패 시 상태를
   올바르게 `FAILED`로 남기는지, 부분 실패 시 롤백/재시도가 일관적인지, `db.delete()` vs bulk delete
   같은 ORM cascade 함정이 다른 곳에도 남아있지 않은지
3. **동시성/세션 안전성**: SSE 스트리밍 중 별도 DB 세션을 여는 `app/api/chat.py`의 `_stream` 같은
   패턴이 커넥션 누수나 레이스 컨디션을 일으킬 가능성이 없는지
4. **AI 로직의 정직성**: `eval_metrics.py`처럼 정답 라벨셋 없이 계산하는 지표가 실제 데이터를 왜곡
   없이 반영하는지, 과장되거나 오해를 부를 수치는 없는지
5. **인증/인가**: JWT 검증(`app/core/deps.py`), 관리자 전용 엔드포인트 보호가 우회 가능한 구멍은
   없는지, 비밀번호 해시(bcrypt) 사용이 안전한지
6. **테스트 커버리지**: `tests/`의 46개 통합 테스트가 실제로 의미 있는 값(추출된 금액, 위험조항
   카테고리 등)을 검증하는지, 단순히 상태코드만 확인하는 얕은 테스트는 없는지

### 출력 형식
다음 형식으로 정리해줘:
1. **강점** (3개 이내, 구체적 근거 파일/라인 포함)
2. **문제점 및 리스크** (심각도 High/Medium/Low로 구분, 각 항목에 해당 파일 경로 명시)
3. **즉시 수정 제안**
4. **AI·Frontend 파트와 합의가 필요한 항목** (Backend 단독으로 결정할 수 없는 것들)

코드 스타일이나 사소한 네이밍 지적보다는, **실제 버그, 데이터 무결성 문제, 보안 허점**에 집중해줘.
