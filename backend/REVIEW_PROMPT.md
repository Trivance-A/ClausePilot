# 리뷰 요청 프롬프트 (다른 AI에게 전달용)

아래 내용을 그대로 다른 AI(예: 별도 세션의 Claude, ChatGPT 등)에게 붙여넣어 검토를 요청하세요.
`backend/` 폴더 전체(README, docs/*.md, app/**)와 `front 폴더/src/types/api.ts`,
`front 폴더/src/mocks/handlers.ts`를 함께 첨부하거나 열람 권한을 주면 됩니다
(백엔드가 실제 프론트 계약과 맞는지 대조하는 것이 이번 리뷰의 핵심이기 때문).

---

## 프롬프트

너는 "AI 기반 계약서 검증 및 규정 챗봇 시스템" 학기 프로젝트의 시니어 백엔드 리뷰어야.
15주 개발계획 중 4주차(설계 단계 1주차) 산출물로 `backend/` 폴더 아래에
DB ERD, API 명세, AI 모듈 연동 인터페이스, 기술스택 결정, FastAPI 프로젝트 골격(스텁 코드)이
작성되었어. 아래 기준으로 리뷰해줘.

### 배경 (판단 기준)
- 프로젝트 목적: 계약서 주요정보 자동추출 + 원문 위치(BBox) 연결 + 위험조항 탐지 + 규정 RAG 챗봇
- 팀 구성: AI·Document 담당 / **Backend·Data 담당(이번 리뷰 대상)** / Frontend·RAG 담당, 총 3명
- 성능 목표: 정보추출 정확도 90%+, BBox 매핑 성공률 95%+, 규정검색 Recall@5 90%+, 근거없는 챗봇 응답 5% 이하, 주요기능 정상동작률 95%+
- 6주차부터 실제 구현이 시작되므로, 4주차 산출물은 "설계가 이후 구현을 막힘없이 진행할 수 있을 만큼 구체적인가"가 핵심 판단 기준
- 학기 프로젝트 범위 조정: EBIZ/KOINS 실연동 제외(Demo UI로 대체), 수기체 OCR 제외, 대규모 Graph DB/Ontology 대신 경량 벡터+키워드 검색

### 리뷰 관점
1. **프론트 계약 일치 여부(최우선)**: `app/api/*.py`의 경로/메서드/상태코드, `app/schemas/*.py`의 필드명이
   `front 폴더/src/types/api.ts` · `src/mocks/handlers.ts`와 정확히 일치하는지 — 특히 FieldCode 8종,
   bbox가 0~1 정규화 좌표인지, 에러 포맷이 `{error:{code,message,detail}}`인지, SSE 이벤트 순서
   (status→token→citation→done)가 맞는지
2. **일관성**: `docs/02_db_erd.md`의 테이블 컬럼과 `docs/03_api_spec.md`의 응답 예시, `app/models/*.py`의 실제 SQLAlchemy 컬럼이 서로 어긋나지 않는지
3. **AI 연동 실현 가능성**: `docs/04_ai_integration.md`에 정의된 `ai_client.py`의 함수 시그니처가 AI 파트(OCR/추출/BBox/위험탐지/하이브리드검색/RAG)의 실제 출력과 맞물릴 수 있는지, 누락된 함수나 애매한 반환 타입은 없는지
4. **BBox/evidence 처리**: 정보추출·위험조항 모두 원문 위치(highlights)를 필수로 다루도록 설계되어 있는지, 필드 근거와 위험조항 근거가 `highlights` 한 테이블에서 정확히 하나의 부모만 갖도록 제약되는지
5. **비동기 처리 설계**: OCR/LLM처럼 오래 걸리는 작업에 대한 상태 추적(`jobs` 테이블) 설계가 실제로 폴링 가능한 수준으로 구체적인지, 실패 처리가 빠져있지 않은지
6. **과설계/과소설계 여부**: 학기 프로젝트 3인 팀 규모에 비해 지나치게 복잡한 구조는 없는지, 반대로 6주차 구현을 시작하기엔 너무 부실한 부분(예: JWT 인증 로직 미구현)은 없는지
7. **5주차 이월 항목의 타당성**: 각 문서 말미의 "5주차로 이월" 항목들이 실제로 4주차에 결정하지 않아도 되는 것들인지, 혹은 지금 결정했어야 하는데 미뤄진 것은 없는지

### 출력 형식
다음 형식으로 정리해줘:
1. **강점** (3개 이내, 구체적 근거 파일/라인 포함)
2. **문제점 및 리스크** (심각도 High/Medium/Low로 구분, 각 항목에 해당 파일 경로 명시)
3. **즉시 수정 제안** (5주차 착수 전 고쳐야 할 것)
4. **AI·Frontend 파트와 합의가 필요한 항목** (Backend 단독으로 결정할 수 없는 것들)

코드 스타일이나 사소한 네이밍 지적보다는, **설계 결함으로 인해 6주차 이후 구현이 막히거나 다시 설계해야 하는 상황이 생길지**에 집중해줘.
