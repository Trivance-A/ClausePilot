# AI 추출 고도화 결과 (feat/ai-upgrade, 2026-11-07)

## 바뀐 것

| 영역 | 이전 | 이번 |
| --- | --- | --- |
| 라벨–값 짝 찾기 | 키워드가 들어간 줄 전체를 값으로 사용 | `ai/extract/rules.py`: `라벨 : 값`(한 줄 여러 쌍), `계약금액 금 …`(콜론 없음), 라벨만 있는 줄 → 다음 줄, 표 셀(왼쪽 셀·위쪽 머리글), `원사업자 \| 수급사업자` 서명표의 역할 열 |
| 병합 셀 표 | 행·열 번호(r,c)로만 구분 → 여러 행에 걸친 라벨은 짝을 못 찾음 | 셀 좌표로 짝: 라벨 행 높이 ±1줄 안의 오른쪽 값, 열이 겹치는 아래 값 → 2행 병합 라벨·세로 글자 라벨·머리글 표 처리 |
| LLM 프롬프트 | `L1-14: [표 r6,c3] 새솔군 …` | `L1-14: [표 r6,c3 · 공사명] 새솔군 …` (값 줄에 라벨 표시, prompt `extract-v5`) |
| LLM이 비운 항목 | null 그대로 | 라벨 옆에 적힌 값으로 채움 (`raw_llm_output._label_fill`에 기록, LLM 답은 덮어쓰지 않음) |
| GPU 없는 환경 추출 | `rule-based-v1` | `rule-based-v2` (위 짝 찾기 사용) |
| 기간 → 이행기일 | 기간 줄 전체를 하이라이트 | 종료일만 값·하이라이트 |
| 계약건명 띄어쓰기 | PaddleOCR가 공백 누락 | 단어 박스 간격으로 공백 복원(`spaced_text`, `PADDLE_WORD_SPACING=1`). Kiwi 띄어쓰기는 정답 35개 중 5개만 일치해 채택하지 않음 |
| OCR 서버 장애 | `OCR_BASE_URL` 서버가 죽으면 문서 실패 | 그 페이지는 CPU OCR로 처리, 60초 뒤 서버 재시도 (`OCR_FALLBACK=0`으로 끔) |

## 측정 (LLM 없이, 규칙 추출기 기준)

`PYTHONPATH=backend:. python -m eval.extraction --gold <dir> --extractor rule --ocr-engine tesseract`
스캔 OCR은 이 환경에 PaddleOCR 모델이 없어 Tesseract로 측정했다 (실서비스는 PaddleOCR).

| 정답셋 | 항목 정확도 | 위치 매핑률 | 위치 정확도(IoU≥0.5) |
| --- | --- | --- | --- |
| 공개 양식 48건 전체 | 35.7% → **87.2%** | 56.5% → 87.0% | 13.4% → 76.3% |
| ├ 텍스트 PDF 35건 | 35.7% → **96.4%** | 61.8% → 97.5% | 15.6% → 88.4% |
| └ 스캔 13건 (Tesseract) | 35.6% → 62.5% | 39.7% → 54.0% | 6.4% → 38.1% |
| 가상 계약서 30건 전체 | 25.4% → 73.3% | 87.7% → 77.7% | 23.2% → 72.7% |
| ├ 텍스트 PDF 20건 | 31.3% → **98.1%** | 92.0% → 100% | 29.5% → 98.0% |
| └ 스캔 10건 (Tesseract) | 13.8% → 23.8% | 78.9% → 31.0% | 9.9% → 19.7% |

공개 양식 항목별(전체): 계약건명 16.7→81.3, 계약금액 58.3→89.6, 보증금액 33.3→81.3, 계약일자 20.8→87.5,
이행기일 14.6→81.3, 보증기간 79.2→95.8, 채권자명 2.1→81.3, 사업자번호 60.4→100 (%).

- 가상 스캔의 매핑률이 내려간 것은 이전 방식이 틀린 줄 전체를 값으로 내서 "매핑은 되지만 값은 틀린" 경우가 많았기 때문. 이번에는 Tesseract가 깨뜨린 값은 비워 둔다.
- 처리 시간: 문서당 평균 3.2초 (변화 없음).

## 아직 측정하지 못한 것

- LLM(vLLM 14B / Ollama 7B) 경로의 정확도: 라벨 힌트(v5 프롬프트)와 빈 항목 보강이 들어갔으므로 AWS 서버에서 재측정 필요.
  `python -m eval.extraction --gold data/gold/forms --extractor llm`
- PaddleOCR 단어 박스 띄어쓰기: paddleocr 버전에 따라 `return_word_box` 출력 키가 다를 수 있어 서버에서 확인 필요 (없으면 이전 동작 그대로).
- GPU OCR 컨테이너 처리 시간 (`eval/ocr_benchmark.py`).
- 백엔드 API 테스트(tests/): Postgres+pgvector가 필요해 이 환경에서는 실행 못 함. ai/tests 124개·eval/tests 20개 통과.
